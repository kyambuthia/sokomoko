# UI and assets

The UI is server-rendered with Go templates. Templates and static files are
embedded in [internal/ui/ui.go](../internal/ui/ui.go).

## Template loading

[internal/ui/templates.go](../internal/ui/templates.go) parses these active
page templates:

- index
- search
- product
- cart
- checkout
- account
- login
- signup
- password_reset_request
- password_reset_confirm
- admin_login
- admin_setup
- staff_signup
- admin
- partner_setup
- partner_dashboard
- partner_products
- partner_product_new
- partner_orders

All active pages share the base templates for base layout, banner, header,
navigation, main content, and footer.

The following files exist under templates/pages but are not parsed by the live
template loader:

- design_showcase.html
- delivery.html
- partner_signup.html
- add_product.html

They are legacy or exploratory files, not live pages.

## Static assets

Static requests are registered under /static/. The handler:

1. rejects path traversal attempts
2. serves a matching file from internal/ui/static on disk when present
3. falls back to the embedded filesystem

Asset URLs are generated through
[internal/ui/assets.go](../internal/ui/assets.go). Local files use modification
time versions; embedded files use short content hashes.

## CSS

The active stylesheet is
[internal/ui/static/stylesheets/styles.css](../internal/ui/static/stylesheets/styles.css).
It is vanilla CSS organized as:

1. design tokens
2. base/reset
3. layout
4. page areas
5. components
6. legacy aliases

The current source uses:

- paper-like light surfaces with a system dark-mode variant
- monospace system fonts
- CSS custom properties for color, type, spacing, radius, borders, shadows,
  layout, and transitions
- mobile-first responsive rules
- component-oriented class names

The CSS source, not the removed historical design reports, defines the actual
visual system.

## JavaScript

JavaScript lives under internal/ui/static/scripts. main.js provides progressive
enhancement and quick-search behavior; search.js contains search-specific
client behavior. Core navigation and forms are intended to remain usable
without JavaScript.

JavaScript requests that carry the session cookie must send the CSRF token in
the X-CSRF-Token header. Current gaps are tracked in
[08-known-issues.md](08-known-issues.md).

## Template change checklist

- Add the page to ParseTemplates if it is a new live page.
- Use the shared base templates.
- Pass Auth.CSRFToken for authenticated unsafe forms.
- Keep form actions same-origin.
- Use the existing asset helper instead of hard-coded cache-busting strings.
- Test the page on the public, admin, or partner host where it is registered.
